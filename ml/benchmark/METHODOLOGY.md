# SNO-15 — методика замера

Для каждой модели выполняются тесты на запрошенных длинах 128 и 512 токенов, batch size = 1.

- 3 прогревочных запуска — не входят в статистику.
- 10 измеряемых запусков.
- Загрузка модели не входит во время инференса.
- Считаются среднее, минимум и максимум времени.
- CPU память: пиковый RSS процесса и прирост RSS во время измеряемых запусков.
- GPU память: torch.cuda.max_memory_allocated() и прирост относительно состояния после загрузки модели.
- Каждая пара модель × устройство запускается в отдельном Python-процессе.

## 128/512 и ограничения моделей

В CSV есть две колонки:

- requested_tokens — длина из задания;
- effective_tokens — фактически использованный лимит модели.

Если штатный лимит модели меньше 512, это не скрывается. Например:

- GLiNER multi-v2.1: max_len = 384 → для requested=512 effective=384;
- paraphrase-multilingual-MiniLM-L12-v2: штатный max_seq_length = 128 → для requested=512 effective=128.

У E5 префикс `passage:` входит в лимит последовательности, поэтому не возникает прежнего переполнения вида 528 > 512.

## NER

Для GLiNER фиксированы labels:
person, organization, city, country, date, event

threshold = 0.5.

## Генеративные keyword-модели

Qwen и ruT5 используют deterministic generation:

- do_sample = False;
- максимум 32 новых токена.

Поэтому их время включает не только обработку входа, но и генерацию результата. Сравнивать скорость корректнее прежде всего внутри одного класса задач.
