# E2E-тесты (SNO-17)

Тесты запускают собранное Electron-приложение из исходников. Предусмотрены два режима:
17 воспроизводимых проверок с управляемыми ответами backend и отдельный настоящий
прогон интерфейса с backend, VK и GLiNER. Windows-установщик этими тестами не проверяется.

## Запуск

Из папки `frontend`:

| Команда                      | Что делает                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------ |
| `npm install`                | установить зависимости (один раз)                                                    |
| `npm run typecheck:e2e`      | проверить типы тестов и конфигурации Playwright                                      |
| `npm run test:e2e`           | проверить типы тестов, собрать приложение в `out/` и прогнать 17 тестов с заглушкой  |
| `npm run test:e2e:live`      | собрать UI для локального API и выполнить реальный прогон с ключом, введённым скрыто |
| `npx playwright test`        | прогнать тесты без пересборки (если `out/` свежий)                                   |
| `npx playwright show-report` | открыть HTML-отчёт последнего прогона                                                |

На Windows можно использовать обычный PowerShell в VS Code. Если он блокирует
`npm.ps1` или `npx.ps1`, вызовите `npm.cmd` или `npx.cmd` с теми же аргументами.
Для обычного `test:e2e` Python, настоящий backend и GLiNER не нужны.

## Что лежит

| Файл                        | Назначение                                                                      |
| --------------------------- | ------------------------------------------------------------------------------- |
| `smoke.spec.ts`             | 3 проверки окна, заглушки и консоли                                             |
| `collection-flow.spec.ts`   | Форма → запуск → экран процесса → возврат к настройкам                          |
| `collection-screen.spec.ts` | 13 проверок статусов, метрик, ошибок, повторов и причин остановки               |
| `helpers/app.ts`            | Запуск Electron с заглушкой и сбор ошибок                                       |
| `helpers/mock-backend.ts`   | Ответы по контракту 0.2.2 и управление прогрессом для каждого сценария          |
| `helpers/collection.ts`     | Заполнение формы искусственными данными                                         |
| `live/launch.mjs`           | Сборка с фиксированным локальным адресом API и запуск Python из backend/.venv   |
| `live/run.py`               | Скрытый ввод ключа, выбор настоящего поста и локальная раздача UI               |
| `live/scenario.mjs`         | Реальная проверка Electron через Playwright без test runner и артефактов отчёта |

Заглушка перехватывает запросы к `http://127.0.0.1:<любой порт>`:
`GET /health`, `POST /vk/validate`, `GET /collection/models`, `POST /collection/start`
и `GET /collection/{collection_id}/progress`.
Заглушка реализует используемые экраном ответы контракта `openapi.yaml` **0.2.2** (SNO-9).
При изменении контракта нужно сверить `helpers/mock-backend.ts` и ожидаемый запрос
в `collection-flow.spec.ts`. Верный токен заглушки — `vk1.a.mock-valid-token`,
любой другой получает 401 `INVALID_TOKEN`. Настоящий токен VK в тестах не используется.

## Что проверяет сценарий

Экран «Параметры сбора» (SNO-5). Элементы ищутся по подписям полей и названиям кнопок,
поэтому при переименовании подписи в интерфейсе нужно поправить и тест.

1. Неверный токен отклоняется с сообщением об ошибке, верный — проходит проверку.
2. Добавляется начальная запись `https://vk.com/club1`; повторный `club1` отклоняется,
   число записей остаётся равным одному.
3. Выбирается GLiNER, типы сущностей `city`. При пороге `1.01` запуск заблокирован;
   при `0.8` становится доступен, нажимается «Начать сбор».
4. В `POST /collection/start` ушло ровно то, что ввели (сверяется весь запрос целиком).
5. Открывается экран «Извлечение данных», показано завершение; кнопка «К настройкам»
   возвращает форму с прежними параметрами.
6. Изменённый токен требует новой проверки: отправка заблокирована.
   В сценарии отправлен ровно один запрос запуска.

Три smoke-теста отдельно проверяют наличие окна, ответ заглушки `/health` и отсутствие
необработанных ошибок JavaScript/сообщений `console.error` при загрузке UI.
Сбор ошибок подключается перед контролируемой перезагрузкой окна с установленной
заглушкой. Перед перезагрузкой helper ожидает начальный `load` нужного file:// URL
и завершение загрузки main-frame в Electron: одно создание окна через `firstWindow`
этого не гарантирует. Это предотвращает отмену ещё ожидаемого `loadFile` и
диалог `ERR_ABORTED (-3)` из обработчика запуска приложения.
Если настройка окна завершается ошибкой, helper закрывает Electron.
Переменные `ELECTRON_RENDERER_URL` и `ELECTRON_RUN_AS_NODE` не передаются дочернему
процессу: тест должен открыть собранный UI в режиме Electron.

13 дополнительных проверок экрана охватывают очередь → сбор → завершение,
метрики, глубину и время, ошибки ML/VK, сохранение последних данных при ошибке
опроса, ручной повтор, отсутствие повтора для 404, обрыв сети, неверные счётчики
и чужой collection_id, уход с экрана и все пять причин остановки.
Остановка опроса проверяется периодом наблюдения дольше интервала 1200 мс.
Подробная область проверки — в [collection-screen-cases.md](collection-screen-cases.md).

## Настоящий прогон UI + backend + VK + GLiNER

Нужны `backend/.venv` с зависимостями backend/GLiNER, доступ к VK и модель
`urchade/gliner_multi-v2.1` (при первом инференсе она загружается).
Закройте другие окна SnowBall и процессы frontend на порту 5173.

В первом терминале из корня проекта:

```powershell
cd backend
.\.venv\Scripts\python.exe main.py
```

Во втором терминале из корня проекта:

```powershell
cd frontend
npm.cmd run test:e2e:live
```

Сначала проверяется запущенный backend. Затем ключ вводится через скрытый запрос
Python `getpass`, без аргумента командной строки и без записи в файл. Выбирается
один из последних пяти текстовых постов публичной группы `vk`; проверяется чтение
поста по ID. Другую группу можно задать через `npm.cmd run test:e2e:live -- --group tpu_official`.

Сценарий проходит настоящий UI: проверка ключа → добавление поста → GLiNER,
threshold 0.5 и глубина 1 → запуск → завершение → сравнение счётчика с API и
проверка доступности постов → возврат к настройкам. Ожидание сбора — до 5 минут.
Один начальный пост и глубина 1 ограничивают число вызовов NER; это не нагрузочный тест.
Ответы сети не подменяются, запросы к VK настоящие. Список постов проверяется
через API, поскольку текущий экран отображает только счётчики, не сами тексты.

Локальный статический сервер на `127.0.0.1:5173` использует origin, уже разрешённый
в CORS backend; настройки приложения ради теста не меняются. Сервер закрывается
после сценария. Адрес API при сборке принудительно фиксируется на `127.0.0.1:8000`.

Ключ передаётся только дочернему процессу сценария и удаляется из его окружения
перед запуском Electron. Ввод в UI выполняется без шага `locator.fill` с ключом.
Live-сценарий использует библиотеку Playwright напрямую: test runner, HTML-отчёт,
трассировка, видео и скриншоты для настоящего ключа не запускаются. Вывод дочернего
процесса дополнительно очищается от точного значения ключа. Тексты VK-постов не печатаются.

Успешный итог:

```text
RESULT: real Electron UI + backend + VK + GLiNER passed
```

`completed` без новых сущностей допустим: результаты зависят от текста настоящего поста.
Ошибка `failed`, сетевая ошибка или таймаут не считаются успешным прогоном.
Таймаут сценария не отменяет уже запущенную задачу backend.

## Границы проверки

Экран SNO-23 запрашивает `/collection/{collection_id}/progress` и показывает
состояние, глубину, время и счётчики. Он пока не отображает `/records` и экспорт.
«Пауза» и «Остановить» сейчас отключены; тесты проверяют именно это поведение,
а не работающие операции остановки/возобновления.

Тесты с заглушкой не подтверждают доступность VK и работу GLiNER. Live-прогон
проверяет реальную интеграцию, но не качество NER на массиве текстов и не установщик.
Обычный E2E-прогон должен закончиться `17 passed`; ошибка `Process failed to launch!`
не является успешной проверкой. Для диагностики запуска можно выполнить в PowerShell:

```powershell
$env:DEBUG = 'pw:browser'
npm.cmd run test:e2e
Remove-Item Env:DEBUG
```
