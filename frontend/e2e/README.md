# E2E-тесты (SNO-17)

Playwright запускает собранное Electron-приложение и подменяет Python-бэкенд заглушкой,
поэтому бэкенд и токен VK для тестов не нужны.

## Запуск

Из папки `frontend`:

| Команда                      | Что делает                                         |
| ---------------------------- | -------------------------------------------------- |
| `npm install`                | установить зависимости (один раз)                  |
| `npm run test:e2e`           | собрать приложение в `out/` и прогнать тесты       |
| `npx playwright test`        | прогнать тесты без пересборки (если `out/` свежий) |
| `npx playwright show-report` | открыть HTML-отчёт последнего прогона              |

## Что лежит

```
e2e/
├── smoke.spec.ts            приложение запускается, заглушка бэкенда отвечает, нет ошибок в консоли
├── collection-flow.spec.ts  токен → начальные записи → модель и порог → запуск → ответ «Задание принято»
└── helpers/
    ├── app.ts               запуск приложения с заглушкой, сбор ошибок консоли
    └── mock-backend.ts      ответы заглушки и журнал запросов интерфейса
```

Заглушка перехватывает запросы к `http://127.0.0.1:<любой порт>`:
`GET /health`, `POST /vk/validate`, `GET /collection/models`, `POST /collection/start`.
Ответы соответствуют контракту `openapi.yaml` 0.2.0 (SNO-9); при его изменении поправить
только `helpers/mock-backend.ts`. Верный токен заглушки — `vk1.a.mock-valid-token`,
любой другой получает 401 `INVALID_TOKEN`. Настоящий токен VK в тестах не используется.

## Что проверяет сценарий

Экран «Параметры сбора» (SNO-5). Элементы ищутся по подписям полей и названиям кнопок,
поэтому при переименовании подписи в интерфейсе нужно поправить и тест.

1. Неверный токен отклоняется с сообщением об ошибке, верный — проходит проверку.
2. Добавляется начальная запись `https://vk.com/club1`.
3. Выбирается GLiNER, типы сущностей `city`, порог `0.8`, нажимается «Начать сбор».
4. В `POST /collection/start` ушло ровно то, что ввели (сверяется весь запрос целиком).
5. На экране «Задание принято бэкендом» и идентификатор из ответа заглушки.

Точки статуса и результатов сбора в контракте пока нет; когда она появится, сценарий
дополняется проверкой результатов.
