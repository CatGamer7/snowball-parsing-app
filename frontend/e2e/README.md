# E2E-тесты (SNO-17)

Playwright запускает собранное Electron-приложение и подменяет Python-бэкенд заглушкой,
поэтому бэкенд и токен VK для тестов не нужны.
Проверяется приложение из исходников, а не Windows-установщик.

## Запуск

Из папки `frontend`:

| Команда                      | Что делает                                                            |
| ---------------------------- | --------------------------------------------------------------------- |
| `npm install`                | установить зависимости (один раз)                                     |
| `npm run typecheck:e2e`      | проверить типы тестов и конфигурации Playwright                       |
| `npm run test:e2e`           | проверить типы тестов, собрать приложение в `out/` и прогнать 4 теста |
| `npx playwright test`        | прогнать тесты без пересборки (если `out/` свежий)                    |
| `npx playwright show-report` | открыть HTML-отчёт последнего прогона                                 |

На Windows можно использовать обычный PowerShell в VS Code. Если он блокирует
`npm.ps1` или `npx.ps1`, вызовите `npm.cmd` или `npx.cmd` с теми же аргументами.
Python, настоящий сервер backend и загрузка GLiNER для прогона не нужны.

## Что лежит

```
e2e/
├── smoke.spec.ts            приложение запускается, заглушка бэкенда отвечает, нет ошибок в консоли
├── collection-flow.spec.ts  токен → начальные записи → модель и порог → запуск → ответ «Задание принято»
└── helpers/
    ├── app.ts               запуск приложения с заглушкой, сбор ошибок консоли
    └── mock-backend.ts      ответы заглушки и журнал запросов интерфейса
```

Заглушка перехватывает запросы к `http://127.0.0.1:<любой порт>`:
`GET /health`, `POST /vk/validate`, `GET /collection/models`, `POST /collection/start`.
Заглушка реализует используемые экраном ответы контракта `openapi.yaml` **0.2.2** (SNO-9).
При изменении контракта нужно сверить `helpers/mock-backend.ts` и ожидаемый запрос
в `collection-flow.spec.ts`. Верный токен заглушки — `vk1.a.mock-valid-token`,
любой другой получает 401 `INVALID_TOKEN`. Настоящий токен VK в тестах не используется.

## Что проверяет сценарий

Экран «Параметры сбора» (SNO-5). Элементы ищутся по подписям полей и названиям кнопок,
поэтому при переименовании подписи в интерфейсе нужно поправить и тест.

1. Неверный токен отклоняется с сообщением об ошибке, верный — проходит проверку.
2. Добавляется начальная запись `https://vk.com/club1`; повторный `club1` отклоняется,
   число записей остаётся равным одному.
3. Выбирается GLiNER, типы сущностей `city`. При пороге `1.01` запуск заблокирован;
   при `0.8` становится доступен, нажимается «Начать сбор».
4. В `POST /collection/start` ушло ровно то, что ввели (сверяется весь запрос целиком).
5. На экране «Задание принято бэкендом» и идентификатор из ответа заглушки.
6. После изменения токена сбрасываются его проверка и результат запуска;
   новая отправка заблокирована до повторной проверки. Отправлен ровно один запрос запуска.

Три smoke-теста отдельно проверяют наличие окна, ответ заглушки `/health` и отсутствие
необработанных ошибок JavaScript/сообщений `console.error` при загрузке UI.
Сбор ошибок подключается перед контролируемой перезагрузкой окна с установленной
заглушкой. Если настройка окна завершается ошибкой, helper закрывает Electron.
Переменные `ELECTRON_RENDERER_URL` и `ELECTRON_RUN_AS_NODE` не передаются дочернему
процессу: тест должен открыть собранный UI в режиме Electron.

Предупреждение Node.js `DEP0190` относится к запуску дочернего процесса с

также не влияет на результат прогона.

## Границы проверки

В контракте 0.2.2 уже есть `/collection/{collection_id}/progress` и
`/collection/{collection_id}/records`, но текущий экран их ещё не запрашивает.
Сценарий подтверждает принятие задания, не завершение реального фонового сбора.
Эти два маршрута заглушкой пока не реализованы. При появлении экрана результатов
нужно добавить их ответы и проверки отображения прогресса и постов.

Тесты не подтверждают доступность VK, качество NER и работу установщика.
Успешный E2E-прогон должен закончиться `4 passed`; ошибка `Process failed to launch!`
не является успешной проверкой. Для диагностики запуска можно выполнить в PowerShell:

```powershell
$env:DEBUG = 'pw:browser'
npm.cmd run test:e2e
Remove-Item Env:DEBUG
```
